Initial thoughts using AI recommendations

1/ Hybrid approach
Start with SB3 to prove the concept works (the environment trains, reward converges, override rate drops). 
Then, if needed for the report, reimplement the core PPO logic from scratch using the SB3 version as a reference/ground truth. 
This gives you:
  A fast working baseline to validate the environment + reward + VL integration
  A from-scratch version you fully understand and can write about
  A way to cross-check: if your from-scratch version diverges from SB3's results, you know there's a bug

2/ Pytorch version
Go CPU-only with latest stable PyTorch (2.6.0). The install command would be:
pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu
pip install stable-baselines3==2.4.1

3/ Normalisation method
The best choice is VecNormalize with both observation and reward normalization.

4/ Tensorboard Logging
TensorBoard is a web-based dashboard that visualises training progress in real-time. You run training in one terminal, 
open TensorBoard in your browser, and watch live charts update as episodes complete.
The install is just:
pip install tensorboard

5/ Checkpointing
Use both periodic checkpoints (safety net) and best-model saving (for the final evaluation). Zero-effort with SB3.

6/ Evaluation entry point
When you run evaluate.py with a trained model, what output format do you want?
Both the console for quick checks, CSV for report figures. The CSV would produce data for plots like:
  Position vs time (train trajectory)
  Speed vs position (speed profile against limits)
  Override rate over the journey
  Reward breakdown per segment
These plots would be strong evidence in the report. The CSV is ~10 lines of extra code.

7/ Episode length cap/truncation
If the agent learns to propose Red (stop) every step, the train never moves. 
The episode never terminates because it never reaches the track end or triggers a collision. 
Training hangs forever on one episode.
Add max_episode_steps=15_000.

8/Seeding / Reproducibility
Without fixed seeds, two identical training runs produce different results. This makes debugging nearly impossible: 
"is the training different because of my code change, or just random variance?"
Add deterministic seeding, 42 is industry standard.

9/ Lead Train Behaviour
Lead train moves at a constant 20 m/s every episode. The agent can effectively "memorise" the exact headway profile.
Start with fixed 20 m/s to get training working. Once you have a converging learning curve, 
switch to randomised per episode to test robustness. 
Variable mid-episode speed is future work.
The fixed speed keeps debugging simple — if training fails, you know it's not because of lead-train randomness.

10/ Scope 
Full training pipeline:
  All 5 files (config.py, agent.py, trainer.py, train.py, evaluate.py)
  SB3 Phase 1 working end-to-end
  Can run python -m think_layer.train and see a learning curve in TensorBoard
  Can run python -m think_layer.evaluate and see metrics
  Verified: training completes, reward trends upward, override rate trends downward
