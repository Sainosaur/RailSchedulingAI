Validation Layer (VL) Documentation
Current Revision: Final Prototype v1.0

1. Why have a Validation Layer?
The RL Agent (PPO) is a non-deterministic black box.
This layer provides absolute mathematical determinism so the AI can undergo aggressive learning and exploration whilst ensuring zero risk of accidents.
PPO is used purely for optimisation; the VL is used for guaranteed, mathematically proven safety.

2. High-Level Architecture
This prototype focuses on a unidirectional convoy model.
It utilises Automatic Train Operation (ATO) Continuous Actions superimposed over standard ETCS Level 2 Fixed-Block infrastructure.

The L2 / Continuous Paradigm:
Environment Constraints (ETCS L2): The track is divided into fixed blocks marked by balises.
The environment tells the train the current signal aspect (0=Red, 1=Yellow, 2=Double Yellow, 3=Green).
AI Action Space: The AI outputs a continuous floating-point throttle command: proposed_a ranging from -1.0 m/s² (Emergency) to +0.5 m/s² (Max Acceleration).

3. The 4-Layer Safety Pipeline

Layer 1: Ingestion & Dynamic Authority
Inputs: x (pos), v (speed), proposed_a, env_aspect (0-3), dtz (dist to zone), d_occ (dist to obstacle).
Logic: 
1. Map env_aspect to Movement Authority (MA). 
   Authority Distance = dtz + (aspect * SH).
   *Special Case (Green Departure Runway)*: If speed < 0.1 and aspect is 3, Authority is dtz + 3*SH to allow departure acceleration.
2. Integrate Physical Reality: Authority is capped by d_occ (actual distance to lead train/hazard).
   dist_avail = min(Authority, d_occ)
3. Dynamic Speed Ceiling: Use reversed SUVAT (v = sqrt(2ad)) with EMERGENCY_DECEL to find the maximum safe entry speed for the next restricted block.

Layer 2: Kinematic Simulation (Adaptive Lookahead)
The VL simulates the train's trajectory over three time horizons sampled at 33%, 67%, and 100% of the segment's total stopping time (t_stop = v_limit / |EMERGENCY_DECEL|).

Checks performed at each sim horizon:
- Spatial Violation: Projected position must not exceed (x + dist_avail).
  *Buffer*: A 2.0m tolerance is granted if stationary (u < 1.0) and at the boundary, to allow the AI to "touch" the platform trigger without violation.
- Kinematic Violation: Projected speed must not exceed the dynamic ceiling for that aspect (+0.5 m/s margin).
- Segment Limit Violation: Projected speed must not exceed the static speed limit of the current or future segment.

Layer 3: The Decision Node (Graduated Interceptor)
Sequence:
1. Hardware Clamp: Ensure action is within [-1.0, 0.5].
2. Stationary Interlock: If aspect is 0 (Red) and speed < 0.1, force a = 0.0 unless braking.
3. Speed Governor: If speed matches the segment limit (within -0.01 margin), cap acceleration to <= 0.0.
4. Trajectory Check: If Layer 2 fails, compute correction:
   a_needed = -u² / (2 * dist_avail)
   Resulting safe_a is clamped between [EMERGENCY_DECEL, 0.0].

Override Severity:
- Distant boundary, low speed  →  gentle correction (coasting or light braking).
- Approaching boundary fast    →  service braking (-0.5 m/s²).
- Imminent spatial breach      →  emergency braking (-1.0 m/s²).

Layer 4: Explainable AI (XAI) Logging
Override events are appended to override_log.csv.
Data Logged: timestamp, original_ppo_a, corrected_a, constraint_id (e.g., Aspect_Spatial_Violation, S1_Limit).
Note: LOG_RESET = True (resets log on each run). LOG_ENABLED can be set to False during high-throughput training to reduce Disk I/O.

5. Safety Constants
- Max Acceleration (ACCEL): 0.5 m/s²
- Emergency Deceleration (EMERGENCY_DECEL): -1.0 m/s²
- Delta T (Step): 1.0 s
- Tolerance Buffer: 2.0 m (for restricted arrivals)

6. Deployment Principles
- Edge Autonomy: Each train hosts its own VL instance. No cloud connectivity required for safety inference.
- ETCS L2 Compatibility: Leverages trackside balises and RBC (Radio Block Centre) for movement authority.

AI Declaration: AI was used iteratively during research and planning. All final safety design choices (logic, formulae, discrete-to-continuous mapping, architectural tracking) were uniquely synthesised for Polish Rail Line 104 specificities.
