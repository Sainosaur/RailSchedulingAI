Validation Layer (VL) Documentation
Current Revision: Final Prototype v2.0 (Arithmetic VL & Log-Only)

1. Purpose
The Validation Layer (VL) provides absolute mathematical monitoring of the RL Agent.
In this version, the VL no longer overrides actions. It acts as a passive safety monitor and logger.
Behavioral shaping is handled by the Reward Function, while the VL provides an audit trail of safety breaches.

2. Architecture
The VL uses arithmetic zone computation based on fixed block geometry.
- O(n) segment lookup: Linear scan over segments.
- O(1) zone arithmetic: All calculations within a segment use direct arithmetic rather than list lookups.
- Modular Design: Adding trains, segments, or obstacles requires no changes to core VL logic.

3. Monitoring Layers

Layer 1: Aspect Computation
Uses zone geometry to compute signal aspects relative to obstacles (lead train or station).
Aspects: 0=Red, 1=Yellow, 2=Double Yellow, 3=Green.
x_diff = x_obs_zone_start - x_ai_zone_end.
Violation (Collision/Overlap) occurs if x_diff <= 0.

Layer 2: SUVAT Stopping Distance Check
Replaces kinematic lookahead with a direct physical check.
Required Stopping Distance: d_stop = u² / (2 * |EMERGENCY_DECEL|).
Spatial Violation occurs if: x_ai_zone_end + d_stop >= x_obs_zone_start.

Layer 3: Constraint Monitoring
- NEGATIVE_SPEED_VIOLATION: Projected speed < 0.0.
- SPEED_LIMIT_VIOLATION: Speed > segment limit.
- ACCEL_NOT_ZERO_VIOLATION: Non-zero acceleration at speed limit or when stationary.
- STATION_SIGNAL_VIOLATION: Attempting to pass a station zone before dwell completion.
- LEAD_TRAIN_SIGNAL_VIOLATION: Accelerating at a Red train aspect.

Layer 4: Logging (Explainable AI)
All violations are appended to `override_log.csv`.
Columns: timestamp, x_ai_zone_end, x_obs_zone_start, ai_speed, constraint_id.

5. Safety Constants
- ACCEL: 0.5 m/s²
- SERVICE_DECEL: -0.5 m/s²
- EMERGENCY_DECEL: -1.0 m/s²
- DT: 1.0 s
