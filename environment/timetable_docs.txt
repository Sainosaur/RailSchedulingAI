RAIL SCHEDULING AI: TIMETABLE & SCHEDULING DOCUMENTATION
Current Revision: Final Prototype v1.0 (Line 104)

File: environment/timetable.py

1. CORE CONCEPT
The Timetable module provides the temporal backbone for the simulation. It generates a realistic, per-station schedule at the start of every episode, accounting for the physical constraints of Line 104 (segment speed limits, acceleration/deceleration buffers) and operational requirements (dwell times, slack).

2. DATA MODELS

A. TimetableEntry
Represents a single station stop on the journey.
- station_idx: Integer index (0 to 6 for Line 104).
- station_name: Human-readable name (e.g., "Chabówka").
- position_m: Exact track meterage of the station.
- scheduled_arrival: Elapsed time (seconds) at which the train should arrive.
- scheduled_dwell: Required waiting time at the platform.
- scheduled_departure: arrival + dwell.

B. Timetable
A container class for a sequence of TimetableEntry objects.
- entries: List of all station stops.
- to_dict(): Serializes the timetable for frontend/dashboard visualization via WebSocket.
- lookup methods: Provides helper functions to find specific station data by index or find the "next" station relative to current progress.

3. KINEMATIC ETA CALCULATION (_compute_segment_travel_time)

The scheduler does not use simple "Distance / Max Speed" math. It employs a trapezoidal/triangular kinematic profile to calculate travel time across segments:
- Acceleration/Deceleration Buffers: Accounts for the time lost while ramping up from a stop or slowing down for a station.
- Trapezoidal Profile: Used for long segments where the train reaches the speed limit (`d_cruise`).
- Triangular Profile: Used for short segments where the train must begin braking before ever reaching the full speed limit.

4. BATCH GENERATION (generate_timetable)

At episode initialization, the `railway_env` calls this function to build the schedule for the AI and Lead trains.
- Slack Factor (Default 1.10): Adds a 10% operational buffer to the raw physical travel time. This ensures the AI has a "recoverable" schedule and isn't penalized for minor stochastic variances.
- Dwell Logic: 
    - Origin (Chabówka): No dwell, departure is at T=0.
    - Intermediate Stations: Standard 120s dwell (configurable).
    - Terminus (Nowy Sącz): No dwell, arrival marks the end of the run.
- Acceleration/Deceleration: Defaulted to 0.5 m/s² for schedule generation to match standard rolling stock performance.

5. LINE 104 STATIONS
The timetable is hardcoded to support the 76km Polish Line 104 traversal:
1. Chabówka (0m)
2. Rabka-Zdrój
3. Mszana Dolna
4. Tymbark
5. Limanowa
6. Marcinkowice
7. Nowy Sącz (76,651m)

6. RUNTIME USAGE
During the simulation, the environment compares the current `sim_time` against the `scheduled_arrival` of the `next_station_idx`. This delta is passed to the reward function to calculate "Punctuality Bonuses" (rewarding early/on-time arrival) or "Lateness Penalties".
